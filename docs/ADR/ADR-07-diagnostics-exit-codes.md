# ADR-07 诊断分级、退出码与 strict

> 状态：已采纳；日期：2026-11-25；适用阶段：P0 起。
> 依据：`slc完整方案.md` §5.1、§9；决策记录 D5/D7。

## 决策

| 退出码 | 含义 |
|---|---|
| 0 | 无 `E`；`W` 存在但未开 `--strict` |
| 1 | 任一 `E`，或 CLI 用法错误（未知参数、缺必填） |
| 2 | 仅 `W` 且启用 `--strict` |
| 3 | 环境/IO：缺目录、端口占用、读写失败、原子替换失败 |

- 唯一实现是 `DiagnosticSink.exit_code(strict=...)`；各命令不得手写映射。
- 诊断码分段：`E01–E15` 核心错误，`W01–W15` 警告，`I01–I08` 信息，`P<PLUGIN>-nn` 领域规则。
- 每条诊断必须有 `file`/`line` 或 `json_path`，尽量带 `hint`。
- `I` 永不改变退出码；`E` 优先于 `W`；`--strict` 只把“仅有 W”提升为 2。

## 理由

CI、pre-commit、编辑器都依赖稳定退出码；把 IO 失败与内容错误分开，才能区分“项目有问题”和“环境没装好”。

## 后果

- 新增命令必须复用 `exit_code`，并补退出码断言测试。
- `W01` 契约提示不是错误；但 `--strict` 下若只有它，退 2，需用户确认。
- `E12`（trace 读写）在 IO 场景按 `io_failure` 返回 3，而不是 1。

## 替代方案

- 所有非零都返回 1：否决，CI 无法区分环境故障。
- 用异常冒泡决定退出码：否决，诊断无法聚合与排序。
