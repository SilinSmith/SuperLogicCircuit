# ADR-04 顶层连线显式化

> 状态：已采纳；日期：2026-11-25；适用阶段：P1 起。
> 依据：`rvgen完整方案.md` §5.4、§0.1 表第 5 条。

## 背景

多 IP SoC 中 `uart.tx` 与顶层 `tx`、`cpu.clk` 与 `uart.clk` 常同名。按同名端口自动连接会把时钟/复位和数据线接错，且错误在编译期不可见。

## 决策

- `top.ports` 是唯一连线依据：`output` 用 `from: module.port`，`input` 用 `to: [module.port...]`。
- 时钟/复位角色用 `role: clock|reset`；**永不参与同名自动连接**。
- 自动推导只产出候选建议，且必须显式 `--accept-wiring` 才落盘（当前未实现该 CLI）。
- 一个源端口被多个输出口引用 → `E13` 并指出冲突双方。
- 模块输入既无 `to` 也无顶层驱动 → `E14` 一次性列出全部缺失。
- 未连接输入可 `top.tieoffs[]` 显式给值。

## 理由

显式映射让顶层接线可评审、可 diff；时钟/复位是全局网络，盲连代价最高。

## 后果

- 新增 IP 必须补 `top.ports`，否则 `check` 报 E14。
- `node_graph` 的 data 边由 `connect`/top 映射推导，不靠名字猜测。
- 候选连线功能是便利项，不是默认行为。

## 替代方案

- 全自动同名连接：否决，多 IP 场景必错。
- 只允许 `connect` 字段、不支持 `top.ports`：否决，顶层引脚无法表达一对多与角色。
